Chat, "reasoning," tool use: the same string, more colors

Tools: get_weather(city), run(cmd) … </system> <user> Umbrella for campus today? </user> <thinking> I need the real forecast, not a guess. </thinking> <tool_call> get_weather("Rochester, NY") </tool_call> ⏸ model stops; harness runs real code <tool_result> {"rain_after":"14:00","p":0.8} </tool_result> Yes. 80% chance of rain after 2 pm. <end>

Reasoning = letting it write intermediate tokens. More compute per hard problem. Not guaranteed faithful.
Tool use = the model only asks. The harness decides. Permissions live here, not in the model.
Agent = this, in a loop, until done. RAG, MCP, Copilot, Claude Code: all this string.
~2 min. This replaces five slides from the draft. The point for a CS audience: there is no second mechanism. Reasoning models, RAG, agents, MCP are all ways of putting more text into this string. MCP = a JSON-RPC schema for "what tools do you have / call this one"; the tool descriptions are just prompt text (which is why MCP servers can prompt-inject).

How a 2026 model is made, and what each stage breaks

1 · Pretraining
Predict next token on ~1013 tokens. 1025–1026 FLOPs, $108+. Mixture-of-experts: ~1T params, ~5% active per token.
✓ knowledge, grammar, code
✗ autocomplete, not an assistant
2 · SFT
Fine-tune on ~105 curated dialogues written by humans or by prior models.
✓ follows the chat format
✗ imitates, including mistakes
3 · RLHF
Humans rank pairs of answers; train toward preferred style.
✓ helpful, polite, safe-ish
✗ sycophancy: optimizes for approval
4 · RLVR
RL on tasks with an automatic checker: math answers, unit tests, CTFs. Thousands of rollouts.
✓ the 2025 jump in code and math
✗ reward hacking: edits the tests
Capabilities are now spiky by verifiability: huge gains where answers can be checked (our field), smaller where they can't.

1026 FLOPs is also the legal line: NY RAISE Act and CA SB 53 define "frontier model" by it.

~1.5 min. Stage 4 is why 2025 was the year coding agents started working: SWE-bench, competition math, CTFs all have checkers. Reward hacking is real: models caught special-casing expected outputs. Same instinct as students gaming a rubric.

2026's new word: recursive self-improvement (RSI)

Claim. Models now do a large share of the work of building the next model.
Anthropic, "When AI Builds Itself" (2026): Claude writes ~80% of production code; picks a better research path than staff 64% of the time (Apr), up from 51% (Nov).
OpenAI: GPT-5.3 Codex (Feb 2026) "first model with a significant hand in its own development." Target: fully automated AI researcher by March 2028; "research intern" Sept 2026.
Doubt. Narayanan: in a 6-day test, agents produced two papers; the original authors rejected both. Marcus: "just faster coding." No agreed metric (Toner, Clark).
Risk. International AI Safety Report 2026 lists loss of control via RSI among top risks. Jack Clark: 60% chance of autonomous self-improvement by 2028.
For us: the research loop is being automated, not only the coding loop. Our PhD training assumes the opposite.

TIME, "What Happens When AI Starts Building AI?" (Aug 7 2026); MIT Technology Review (Aug 18 2026); Fortune (Sep 19 2026).

~1.5 min. Be balanced: this is a claim labs make about themselves. But the numbers they publish (80% of code, 2× experiments per researcher) are in the same direction as what we see in our own labs.

Plan vs. act mode = same model, different prompt, read-only tools switched on.
Sub-agents get a short brief and a fresh context, return a summary. Not the full history.
Done is whatever the checker accepts. A bad checker gets a bad fix (tests edited to pass).
~1 min. Click through fast. This is also the fallback if the live demo fails.

Most of the product is the harness, not the model

Context engineering. What goes in the window and when: compaction, summaries, sub-agent isolation.
Serving tricks. KV cache (n² → n per token), prompt caching (0.1× price), speculative decoding (2–3× faster).
Verification. Tests, type checkers, a second model as reviewer. The agent is only as good as its checker.
Systems, PL, SE, HCI, security: every one of these boxes is our research area.
~1.5 min. Pitch: the open problems in agents are classic CS problems wearing a new hat. Scheduling context is memory hierarchy; verifiers are testing/PL; permissions are OS/security; MCP is API design.

The unsolved hole: prompt injection. Toggle the three ingredients

Agent can read private data
Agent reads untrusted content
Agent can send data out
Pick capabilities
EchoLeak (CVE-2025-32711, CVSS 9.3): one email → Copilot exfiltrates OneDrive/Teams data. 2026: Copilot Studio, Agentforce, Grafana; a coding-agent triage bot poisoned an npm package (~4,000 dev machines).

Simon Willison, "The lethal trifecta" (2025); Meta, "Agents Rule of Two" (2025); OWASP GenAI Exploit Round-up Q1 2026; OECD AI Incidents (Apr 2026).

~1.5 min. Flip the switches. Any two: survivable. All three: data theft is a matter of time, because instructions and data are the same string and no filter is reliable. Meta's Rule of Two: an unsupervised agent holds at most two. This is a security course lab waiting to be written.

The classroom
What MIT concluded, and what still needs teaching

MIT's institute-wide report, August 13, 2026

"Already these technologies can produce credible solutions and provide reasonable responses to almost any written assignment in our undergraduate curriculum."MIT Ad Hoc Committee on AI Use in Teaching, Learning, and Research Training. 8 principles, 26 recommendations.
Design. Start from course goals, make them "AI-aware," then choose assessments (backward design).
Assess. Oral exams, portfolios, in-class conversations about take-home work, version history as evidence. Proctored exams: "a better choice in most cases."
Policy. Every course states its AI policy from a standard menu (permit / limit / require / forbid). "AI Light" and "AI Heavy" pathways.
Teach it. From orientation onward; "AI-Intensive in the Major" courses. Two-thirds of students expect AI to matter to careers; 25% feel prepared.

aiandeducation.mit.edu/report. Principles include: be humble, be bold, lean into learning, augmentation not automation, no one size fits all.

~1.5 min. This is the most thorough institutional answer so far, and it's from a place where every student can code. Note what they did NOT do: no detection tools, no blanket ban.

Five things to take back to your office

1. One string, one loop. Reasoning, RAG, agents, MCP: all text in the window. There is no second mechanism.
2. The curve: ~4–7 month doubling of task length, ~10× a year cheaper. Plan for the 2028 model, not the 2026 one.
3. Capability follows verifiability. Our field is the most verifiable. It moves first.
4. Prompt injection is unsolved. Any agent with data + untrusted input + egress is a breach waiting. Teach it, research it.
5. Every course gets an AI policy and an AI-aware assessment this year. Run your own assignment through an agent first.
~1 min. Then plug AI Committee resources and the hands-on sessions.
